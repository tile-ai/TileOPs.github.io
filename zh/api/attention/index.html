    Attention Operators¶

    本页暂无中文版。以下为英文原文。

    Every op on this page is used the same way: construct it once, then call it. The constructor takes what the kernel is compiled with; the call takes the tensors. Both are documented under each op — __init__ and forward, where forward is what runs when you call op(...).

    Multi-Head Attention¶

    tileops.attention.MHAPagedFwdOp ¶

    Paged Multi-Head Attention (MHA) decode with dynamic KV cache. Layout: Q \([batch \times seqlen\_q \times heads \times dim]\) (BSHD); k_cache, v_cache physical cache [seqlen_kv, heads, dim]; block_table [batch, num_pages]; cache_seqlens [batch].

    A causal call aligns the queries to the end of each request's cache: query i sees the keys up to position i + cache_seqlens - seqlen_q. A query that sees no key outputs zeros. The op takes no sm_scale; scores are scaled by dim ** -0.5.

    Grouped-Query Attention¶

    tileops.attention.GQADenseBwdOp ¶

    Grouped-Query Attention (GQA) backward over dense tensors. Layout: BSHD.

    The backward of :class:GQADenseWithLSEFwdOp over a square call (\(S_q = S_{kv} = S\)): o and lse are the pair that forward returns, and the parameters mean what the forward's do. lse is the float32 natural-log log-sum-exp of each query row's scaled scores, [B, H, S]; a row with lse -inf saw no key and gets zero gradients.

    The in-tree kernels serve window_size_left = window_size_right = -1 and no softcap; a call with either is refused when a kernel is selected, naming the limit. Pass them anyway, equal to the forward's, so a refused call says why.

    tileops.attention.GQADenseFwdOp ¶

    Grouped-Query Attention (GQA) over dense \(Q\)/\(K\)/\(V\) tensors, layout BSHD.

    Every batch entry has one query length \(S_q\) and one KV length \(S_{kv}\). The \(H\) query heads form \(H_{kv}\) groups of \(g = H / H_{kv}\); head \(h\) reads KV head \(r(h) = \lfloor h / g \rfloor\). Query row \(i\) sits at KV position \(p_i = i + S_{kv} - S_q\). With \(\alpha\) = sm_scale (default \(1/\sqrt D\)), \(c\) = softcap and \(\sigma_h = \exp(\mathrm{sinks}_h)\), or \(0\) without sinks:

    \[ \begin{aligned} Z_{h,i,j} &= \alpha\,\langle Q'_{i,h}, K'_{j,r(h)} \rangle, \qquad L_{h,i,j} = \begin{cases} c\tanh(Z_{h,i,j}/c) \text{ if } c > 0, \text{ else } Z_{h,i,j}, & j \in \mathcal V_i, \\ -\infty, & j \notin \mathcal V_i, \end{cases} \\ O_{i,h} &= \sum_j \frac{\exp L_{h,i,j}}{\sigma_h + \sum_k \exp L_{h,i,k}}\,V'_{j,r(h)}. \end{aligned} \]

    Key \(j\) is in the visible set \(\mathcal V_i\) when is_causal is off or \(j \le p_i\), and it lies within window_size_left keys left and window_size_right keys right of \(p_i\), -1 meaning unlimited. \(Q'\) and \(K'\) are \(Q\) and \(K\) times q_scale and k_scale for FP8 input, rotated under pos_encoding_mode="rope" at positions \(p_i\) and \(j\); \(V'\) is \(V\) times v_scale. A sink is neither scaled nor capped, and the in-tree kernels serve sinks on SM90 only. Accumulation is FP32; the output takes the input dtype, or out_dtype for FP8 input.

    tileops.attention.GQADenseWithLSEFwdOp ¶

    Dense Grouped-Query Attention (GQA) forward that also returns each query row's log-sum-exp, the pair :class:GQADenseBwdOp takes.

    It computes the output of :class:GQADenseFwdOp over 16-bit \(Q\)/\(K\)/\(V\) with the same causal mask, window, score scale and softcap, and adds

    \[ \mathrm{lse}_{h,i} = \log \sum_{j \in \mathcal V_i} \exp(L_{h,i,j}), \]

    the natural-log log-sum-exp of the scaled, capped and masked logits. Its reference is flash_attn_interface._flash_attn_forward, the forward of FlashAttention-3's training path; softmax_scale is sm_scale here and causal is is_causal.

    The in-tree kernels serve it on SM90 for prefill (\(S_q > 1\)) without a window; any other call is refused when a kernel is selected.

    tileops.attention.GQAPagedFwdOp ¶

    Grouped-Query Attention (GQA) over a caller-owned paged KV cache.

    Packed Q and its cumulative sequence lengths cover both prefill and decode. block_table maps logical pages to physical entries in k_cache and v_cache. This Op reads the cache only: allocation, append, and mutation remain runtime responsibilities. The in-tree kernels serve a call in which Q and the cache share a float16 or bfloat16 dtype, or in which the cache, and optionally Q, is float8_e4m3fn, over any positive page size and any mix of per-request query lengths, a request with no query token included. Optional float32 sinks contribute a logit per query head to the softmax denominator only: they are not scaled or softcapped; -inf disables a sink and +inf makes that head's output zero. A query row with no visible key returns zero, including when its sink is disabled. RoPE rotates Q and cached K in NeoX or interleaved layout, including a partial rotary width. The table must cover every request's cache length.

    An FP8 operand is dequantized by its float32 scales: q_scale per request and KV head, k_scale and v_scale per tensor or per request and KV head. Its stored values enter the products exactly, in a 16-bit type, and the probabilities stay 16-bit; with an FP8 query the products run in float16 whatever out_dtype is. RoPE rotates the dequantized query and keys, rounded to the output dtype.

    The Hopper RoPE path may allocate up to 512 MiB of temporary storage per call: the rotated Q and rotated key channels (all of the dequantized K and V over an FP8 cache). Under CUDA Graph capture, the graph pool retains that storage. Its allocation is bounded by the page-table and rotary-table extents; preparation writes only live cache pages, including the last page's padding. Calls exceeding this budget use fused rotation without expanded KV storage. Device lengths stay live replay inputs; choosing and preparing this path requires no host readback.

    Append with PagedKVCacheWriteFwdOp using physical slots, then read with post-append lengths. For rotated caches, apply RoPENeoxPositionIdsFwdOp to new Q/K before writing and use pos_encoding_mode="none" to avoid double rotation. FP8 writes quantize new K/V before attention; the retired fused append op attended those tokens at their original 16-bit precision.

    The Hopper FP8-query prefill path keeps up to 64 MiB per call geometry and stream for the partial outputs of short requests whose keys it splits across work items; a captured graph takes its own copy from the graph pool.

    The caller guarantees well-formed cu_seqlens_q, or passes validate_inputs=True, which checks it on the CPU on every call.

    tileops.attention.GQAVarlenFwdOp ¶

    Grouped-Query Attention (GQA) over packed THD tensors.

    cu_seqlens_q and cu_seqlens_kv delimit each request. The interface covers both prefill and decode; tensor geometry and sequence metadata come from each call, while mask, score, out_dtype, and RoPE semantics are fixed at construction. The BUILTIN path implements 16-bit regular and sliding-window attention, with or without fused RoPE. Optional float32 sinks contribute a logit per query head to the softmax denominator only: they are not scaled or softcapped; -inf disables a sink and +inf makes that head's output zero. A query row with no visible key returns zero, including when its sink is disabled.

    float8_e4m3fn Q/K/V are dequantized by one q_scale, k_scale and v_scale per request and KV head, and name a 16-bit out_dtype; the FP8 result carries the error of a single e4m3 rounding of the softmax weights, so it agrees with the 16-bit path to about 2% relative.

    By default the op does not check the contents of cu_seqlens_q and cu_seqlens_kv. The kernels read and write the packed tensors at the positions the offsets name. Malformed offsets can cause out-of-bounds accesses or incorrect results. The caller guarantees well-formed offsets, or passes validate_inputs=True, which checks them on every call at the cost of a device synchronization and cannot run inside CUDA Graph capture.

A cache row is FlashMLA's DeepSeek-V3.2 FP8 layout: 512 float8_e4m3fn latent values, one float32 scale per 128 of them, then 64 bfloat16 rope values. The key is the dequantized latent and the rope; the value is the dequantized latent. A position of -1, or at or past cache_seqlens, is dead.

    The kernel rounds the dequantized key and the softmax weights to bfloat16 before their matmuls, which accumulate in float32. lse is the natural-log sum of exponentials of the scaled scores; a row with no live position returns zeros and lse -inf. Serves SM89 and SM90, 64 or a multiple of 64 heads, topk a multiple of 64, and a cache below 2^32 bytes.

    Attention indexing¶

    tileops.attention.FP8LightningIndexerFwdOp ¶

    Lightning indexer logits over FP8 index keys.

    For query s and key t of group g, the logit sums weights[s, h] times relu(q[s, h] . k[t, g]) over the heads of group g, for keys inside the query's window [starts[s], ends[s]). A bf16 call is quantized to FP8 by the op; an FP8 call passes the per-key scales in index_k_scale.

    On SM90, a one-batch-row call with one key group and 512 or more 64-key tiles whose query blocks leave a partial last wave sums (x + |x|) * weight, twice the relu term, and halves the head sum. Its logits equal the relu sums unless a term or partial head sum has magnitude below 2^-126, kept doubled where denormal flushing would drop it, or at least 2^127, which overflows.

    Paged KV Cache¶

    tileops.attention.PagedKVCacheWriteFwdOp ¶

    Scatter new K/V rows into the page pools in place, the write half of a paged cache.

    The slots come from the caller as one flattened row index per token, -1 skipping the token, so the pages a call writes need not be consecutive, need not be new, and need not belong to one request: a prefix-caching server reuses a page it already holds and a chunked prefill writes the pages it was just given. Distinct non-negative slots are the caller's obligation, and a call writes nothing outside the slots it names. With an FP8 cache the rows are divided by their scale and cast to E4M3FN. NaN is preserved; finite overflow and infinities saturate to the largest finite magnitude with the same sign.

    tileops.attention.MLAKVCacheWriteFwdOp ¶

    Write the MLA latent and rope key of new tokens into a paged cache, in place.

    Each token's row is its kv_c followed by its k_pe, the cache layout of MLAPagedFwdOp. The slots come from the caller as one flattened row index per token, -1 skipping the token; distinct non-negative slots are the caller's obligation, and a call writes nothing outside the rows it names. With fuse_rope the k_pe half of the row is rotated at the token's position as it is written; k_pe itself is not modified. Each rotated value is computed in float32 and rounded once to the input dtype, so it can differ by a step of that dtype from a rotation evaluated in 16-bit arithmetic. With an FP8 cache the row is divided by kv_scale and cast to E4M3FN. NaN is preserved; finite overflow and infinities saturate to the largest finite magnitude with the same sign.
